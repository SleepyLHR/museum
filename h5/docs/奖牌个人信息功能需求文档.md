# 奖牌个人信息功能需求文档

## 1. 项目背景

当前"文物拼图大挑战"H5小游戏部署在腾讯云 CloudBase 静态托管上，通过微信公众号推送文章中的"阅读原文"链接跳转访问。用户完成全部5关拼图后，会弹出电子荣誉证书（奖牌页面）。当前奖牌页面仅显示固定文案，缺少用户个性化信息。

## 2. 需求概述

在最终奖牌（电子荣誉证书）中添加个人信息：用户昵称、关卡总耗时、奖牌编号，并提供证书保存和排行榜功能。

## 3. 功能需求

### 3.1 用户昵称

| 项目 | 说明 |
|------|------|
| 来源优先级 | 设置页手动输入昵称 > "神秘玩家" |
| 显示位置 | 证书正文，突出显示 |
| 手动输入 | 在设置页面增加昵称输入框，用户可随时修改 |
| 技术方案 | 用户在设置页手动输入昵称；未输入则降级为"神秘玩家" |
| 持久化 | 昵称存入 localStorage，避免重复输入 |

**昵称获取优先级流程**：

```
1. 检查设置页是否手动输入过昵称
   → 有：使用手动输入的昵称
   → 无：使用"神秘玩家"
```

**设置页昵称输入功能**：

| 项目 | 说明 |
|------|------|
| 入口 | 设置页面，用户头像/名称区域点击可编辑 |
| 输入方式 | 文本输入框，支持中英文 |
| 字数限制 | 最多12个字符 |
| 保存时机 | 输入框失焦或点击确认时自动保存 |
| 持久化 | 存入 localStorage |
| 显示 | 设置页用户区域实时显示当前昵称 |

### 3.2 关卡总耗时

| 项目 | 说明 |
|------|------|
| 定义 | 用户完成全部5关拼图所用时间的总和 |
| 计时规则 | 从用户进入某一关游戏页面开始计时，到该关拼图完成时停止计时，5关计时相加 |
| 显示格式 | X分X秒（如：3分25秒） |
| 显示位置 | 证书正文，昵称下方 |
| 持久化 | 每关耗时存入 localStorage，完成全部关卡后汇总 |

### 3.3 奖牌编号

| 项目 | 说明 |
|------|------|
| 格式 | BM + 年份(4位) + 时间戳后7位，如 BM2026XXXXXXX |
| 唯一性 | 基于时间戳生成，确保编号唯一 |
| 显示位置 | 证书底部 |
| 生成时机 | 用户完成第5关时自动生成 |
| 持久化 | 编号存入 localStorage，同一用户重复查看证书显示相同编号 |

### 3.4 证书保存

| 项目 | 说明 |
|------|------|
| 功能 | 用户点击"保存证书"按钮，将证书页面保存为图片到手机 |
| 实现方式 | 将证书DOM节点渲染为Canvas，导出为PNG图片，触发下载 |
| 保存格式 | PNG图片 |
| 图片内容 | 完整证书页面，包含昵称、总耗时、奖牌编号、日期等信息 |

### 3.5 排行榜

| 项目 | 说明 |
|------|------|
| 功能 | 展示用户完成全部5关的耗时排名 |
| 排名依据 | 按关卡总耗时升序排列（耗时越短排名越高） |
| 数据来源 | localStorage 存储的历史完成记录 |
| 展示内容 | 排名、昵称、总耗时、奖牌编号 |
| 限制说明 | 纯前端方案，排行榜数据仅限当前设备/浏览器，不支持跨设备数据同步 |

## 4. 技术方案

### 4.1 昵称获取流程

```
用户进入H5页面
  → 检查localStorage中是否已保存手动输入的昵称
    → 有：直接使用已保存的昵称
    → 无：使用"神秘玩家"
  → 用户可在设置页面随时修改昵称
    → 输入昵称后保存至localStorage
    → 证书页面同步更新显示
```

### 4.2 关卡计时流程

```
用户进入某一关游戏页面 → 记录开始时间 startTime
  → 用户完成拼图 → 记录结束时间 endTime
    → 计算本关耗时 duration = endTime - startTime
      → 存入 localStorage（key: level1Time, level2Time, ...）
        → 完成第5关时，汇总5关耗时
```

### 4.3 奖牌编号生成规则

```
编号 = "BM" + 当前年份(4位) + 当前时间戳后7位
示例：BM2026837291
```

### 4.5 证书保存方案

```
用户点击"保存证书"
  → 使用 html2canvas 或 Canvas API 将证书DOM元素渲染为图片
  → 将Canvas导出为PNG格式的Data URL
  → 创建隐藏的 <a> 标签，设置 href 为图片Data URL，download 为文件名
  → 自动触发下载（或微信环境下触发长按保存）
```

> **技术选型建议**：优先使用 html2canvas 库（轻量、兼容性好），或使用原生 Canvas API 自行绘制证书内容。

### 4.6 排行榜技术方案

```
数据结构（localStorage key: rankList）：
[
  {
    nickname: "玩家昵称",
    totalTime: 205,          // 总耗时，单位秒
    medalNumber: "BM2026837291",
    completedAt: "2026-05-07T10:30:00"
  },
  ...
]

排序规则：按 totalTime 升序排列
去重规则：同一 medalNumber 只保留最佳成绩（耗时最短）
展示规则：默认显示前20名，支持查看更多
```

### 4.7 技术约束

| 约束项 | 说明 |
|--------|------|
| 部署环境 | 腾讯云 CloudBase 静态托管（纯前端，无后端服务器） |
| 数据存储 | 前端 localStorage 存储，用户清除浏览器数据会丢失 |
| 跨设备 | 不同设备/浏览器无法共享数据，同一用户在不同设备上会生成不同编号 |

## 7. 验收标准

1. 完成全部5关后，证书中正确显示用户昵称（手动输入昵称 > "神秘玩家"）
2. 设置页面支持手动输入和修改昵称，最多12个字符
3. 证书中正确显示5关总耗时，格式为"X分X秒"
4. 证书中显示唯一编号，格式为"BM" + 年份 + 时间戳后7位
5. 同一用户重复查看证书，三项信息保持一致
6. 未设置昵称时，证书中显示"神秘玩家"
7. 计时精确到秒
8. 点击"保存证书"可将证书保存为PNG图片到手机
9. 排行榜按总耗时升序展示完成记录，支持查看历史排名
