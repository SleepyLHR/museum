# 后端功能需求文档 v2.0

> 项目：文物拼多多 · 博物馆拼图游戏
> 版本：v2.0（微信混合授权 + Node.js 后端）
> 部署环境：Linux 云服务器 + Nginx + Node.js
> 认证服务：微信认证服务号（已具备）

---

## 1. 项目背景与目标

### 现状

当前为纯前端 H5 应用，所有数据存储在浏览器 localStorage 中：

| 问题 | 影响 |
|------|------|
| localStorage 隔离 | 换设备/清缓存后数据全部丢失 |
| 证书编号基于时间戳 | `BM2025+7位数字`，无法实现递增编号 |
| 无服务端 | 无法做排行榜、用户统计 |
| 编号不可验证 | 无法判断证书真伪、无法防伪造 |
| 无用户身份 | userId 仅展示用，不关联任何业务数据 |

### 目标

- **用户无感登录**：微信内完全静默授权（零弹窗），微信外匿名注册
- **用户数据服务端化**：游戏进度、关卡用时、证书等全部持久化到服务端
- **跨设备一致性**：同一微信用户，换设备后自动识别，历史数据完整保留
- **递增证书编号**：000001→999999，逢特殊数字自动识别中奖
- **排行榜**：日榜 + 总榜

### 2.2 两种登录通道

| 通道 | 触发条件 | 用户操作 | 身份标识 | 跨设备 |
|------|----------|----------|----------|--------|
| **微信静默授权** | User-Agent 包含 MicroMessenger | 零操作，完全无感 | OpenID | ✅ 同一微信号自动识别 |
| **匿名注册** | 非微信环境（浏览器/其他App） | 零操作，自动完成 | 服务端生成匿名ID | ❌ 换设备需证书找回 |

**核心设计原则**：localStorage 仅作为本地缓存层，**服务端数据为唯一真实来源**。

### 2.3 技术选型

| 组件 | 选择 | 说明 |
|------|------|------|
| 运行时 | Node.js 18+ | 与前端语言统一 |
| 框架 | 原生 `http` 模块 | 功能简单，无需 Express |
| 数据库 | SQLite (better-sqlite3) | 单文件零配置 |
| 进程管理 | pm2 | 自动重启、日志管理 |
| 端口 | 3001（内网） | Nginx 反向代理 |
| 微信 SDK | 原生 HTTPS 调用 | 无需第三方 SDK |
| SSL | Let's Encrypt（免费） | Nginx 配置 |
| 认证凭证 | AppID（前端）+ AppSecret（服务端） | AppSecret 绝对不能暴露到前端 |

## 3. 数据库设计 (SQLite)

### 3.1 users — 用户表

```sql
CREATE TABLE users (
  id               TEXT PRIMARY KEY,      -- 服务端生成: "U"+时间戳base36
  openid           TEXT UNIQUE,           -- 微信OpenID，微信用户独有
  token            TEXT NOT NULL UNIQUE,  -- 32位hex随机字符串，Bearer认证
  nickname         TEXT DEFAULT '神秘玩家',
  avatar           TEXT,                   -- 微信头像URL（暂不使用，预留）
  -- 游戏进度（服务端存储，换设备可完整恢复）
  unlocked_levels  TEXT DEFAULT '["level1"]',   -- JSON数组
  completed_levels TEXT DEFAULT '[]',            -- JSON数组
  level_times      TEXT DEFAULT '{}',            -- JSON对象 {levelId: seconds}
  total_time       INTEGER DEFAULT 0,            -- 各关累计总用时（秒）
  -- 通关与证书
  has_completed     INTEGER DEFAULT 0,            -- 0=未通关 1=已通关
  cert_number      TEXT,                          -- 关联certificates表
  first_completed_at TEXT,                       -- 首次通关时间 ISO8601
  -- 排行榜快照
  rank_nickname    TEXT,                          -- 通关时锁定的昵称
  rank_total_time  INTEGER,                       -- 通关时锁定的总用时
  -- 元数据
  created_at       TEXT NOT NULL,                  -- ISO 8601
  last_active_at   TEXT NOT NULL,
  is_anonymous     INTEGER DEFAULT 1               -- 1=匿名用户 0=微信用户
);
```

**设计要点**：
- `openid` 与 `id` 分离：`openid` 仅微信用户有，用于跨设备识别；`id` 是通用标识
- `level_times` / `total_time` 同步到服务端，换设备后从服务端恢复
- `rank_nickname` / `rank_total_time` 是通关快照，用于排行榜展示
- `unlocked_levels` / `completed_levels` 同步到服务端，换设备完整恢复

### 3.2 certificates — 证书表

```sql
CREATE TABLE certificates (
  cert_number   TEXT PRIMARY KEY,    -- "000001" ~ "999999"
  user_id       TEXT NOT NULL,
  nickname      TEXT NOT NULL,       -- 通关时锁定的昵称快照
  total_time    INTEGER NOT NULL,   -- 通关时锁定的总用时（秒）
  is_special    INTEGER DEFAULT 0,  -- 0=普通 1=特殊号码
  prize         TEXT,               -- 奖品名称，普通为 NULL
  created_at    TEXT NOT NULL,      -- ISO 8601
  FOREIGN KEY (user_id) REFERENCES users(id)
);
```

### 3.3 cert_counter — 编号计数器

```sql
CREATE TABLE cert_counter (
  id             INTEGER PRIMARY KEY DEFAULT 1,
  current_value  INTEGER NOT NULL DEFAULT 0
);
-- 初始: INSERT INTO cert_counter (current_value) VALUES (0);
```

**原子递增（伪代码）**：
```
BEGIN TRANSACTION
  UPDATE cert_counter SET current_value = current_value + 1
  SELECT current_value FROM cert_counter
COMMIT
→ 格式化为6位: String(value).padStart(6, '0')
```

### 3.4 scores — 总榜成绩表

```sql
CREATE TABLE scores (
  user_id    TEXT PRIMARY KEY,
  nickname   TEXT NOT NULL,      -- 排行榜展示用（通关快照）
  total_time INTEGER NOT NULL,   -- 当前最佳总用时
  cert_num   TEXT,               -- 证书编号（可选展示）
  updated_at TEXT NOT NULL,
  FOREIGN KEY (user_id) REFERENCES users(id)
);
```

### 3.5 daily_scores — 日榜成绩表

```sql
CREATE TABLE daily_scores (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id    TEXT NOT NULL,
  nickname   TEXT NOT NULL,
  total_time INTEGER NOT NULL,
  score_date TEXT NOT NULL,       -- "2026-05-09"
  created_at TEXT NOT NULL,
  FOREIGN KEY (user_id) REFERENCES users(id)
);
CREATE INDEX idx_daily_date_time ON daily_scores(score_date, total_time);
```

## 4. API 设计

全部接口前缀：`/api`

### 4.1 微信授权类

#### GET /api/wx/oauth

> 前端重定向入口（前端自己拼微信授权链接），此接口仅供文档说明

前端在微信环境下直接跳转到：
```
https://open.weixin.qq.com/connect/oauth2/authorize
  ?appid=<AppID>
  &redirect_uri=https://<你的域名>/api/wx/callback
  &response_type=code
  &scope=snsapi_base
  &state=<随机字符串>
  #wechat_redirect
```

#### GET /api/wx/callback

> 微信回调接口，接收 code，换 OpenID，识别/创建用户，重定向回前端

请求：
```
GET /api/wx/callback?code=xxxxx&state=yyyy
```

服务端处理流程：
1. 用 code + AppSecret 向微信服务器换 OpenID
2. 用 OpenID 查 users 表
   - **找到** → 老用户 → 生成新 token，更新 `last_active_at`
   - **未找到** → 新用户 → 创建记录，生成 token
3. 302 重定向到前端：`https://<域名>/#/?token=<新token>`

返回：302 重定向，无 JSON 响应体

错误：
- code 无效或已过期 → 重定向到 `https://<域名>/#/home?error=wx_auth_failed`
- AppSecret 错误 → 记录错误日志，返回 500

**注意**：此接口同时处理微信服务器到你的服务器的回调，以及你到前端的重定向。两次重定向分别是：微信→服务端（GET /api/wx/callback）和 服务端→前端（302 到前端）。

#### GET /api/wx/jsapi-config

> 获取微信 JS-SDK 签名（预留，后续分享、支付等可能用到）

请求参数：
```
?url=https://museum.com/game/level1
```

响应：
```json
{
  "appId": "wx1234567890abcdef",
  "timestamp": 1746938456,
  "nonceStr": "randomstr123",
  "signature": "xxxxxxxxxxxx"
}
```

```

```


```json
{}
```

响应（微信用户）：
```json
{
  "userId": "U1a2b3c4",
  "token": "已有token或新token",
  "nickname": "神秘玩家",
  "hasCompleted": false,
  "unlockedLevels": ["level1", "level2"],
```

```json
{
  "userId": "U5x7y9z1",
  "token": "a1b2c3d4e5f6...32位hex",
  "nickname": "神秘玩家",
  "hasCompleted": false,
  "unlockedLevels": ["level1"],
  "completedLevels": [],
```

- 返回完整的用户游戏进度，前端直接覆盖本地缓存



### 4.3 证书类

#### POST /api/cert/apply

> 首次通关时申请证书编号

请求头：
```
Authorization: Bearer <token>
```
请求体：
```json
{
  "totalTime": 360,
  "nickname": "张三",
  "levelTimes": { "level1": 30, "level2": 45, "level3": 60, "level4": 90, "level5": 135 }
}
```

响应：
```json
{
  "certNumber": "000888",
  "isSpecial": true,
  "prize": "三等奖 - 精美文创礼品",
  "totalCerts": 888
}
```

**幂等处理**：
- 服务端校验 `has_completed == 1` → 已领过 → 直接返回已有 certNumber，不重新递增

**服务端逻辑**：
1. 验证 token → 获取 userId
2. 检查该用户是否已领过证书 → 若已领，返回已有编号（幂等）
3. 原子递增计数器 → 生成 6 位编号
4. 检测特殊号码规则 → 匹配则标记 is_special + prize
5. 写入 certificates 表
6. 更新 users 表：`has_completed=1, cert_number=xxx, first_completed_at=now, rank_nickname=xxx, rank_total_time=xxx`
7. 更新 scores 表（插入或更新）
8. 返回结果

**特殊号码检测规则（配置文件 `special-rules.json`）**：

```json
{
  "specials": [
    { "rule": "endsWith", "value": "888", "prize": "三等奖 - 精美文创礼品" },
    { "rule": "endsWith", "value": "666", "prize": "三等奖 - 精美文创礼品" },
    { "rule": "endsWith", "value": "000", "prize": "参与奖 - 博物馆纪念贴纸" },
    { "rule": "exact",  "value": "000001", "prize": "特别奖 - 首位通关大礼包" },
    { "rule": "exact",  "value": "100000", "prize": "里程碑奖 - 十万通关纪念品" },
    { "rule": "exact",  "value": "500000", "prize": "里程碑奖 - 五十万通关纪念品" },
    { "rule": "exact",  "value": "999999", "prize": "终极奖 - 百万通关大礼包" },
    { "rule": "pattern","value": "^(\\d)\\1{5}$", "prize": "二等奖 - 限量文创套装" }
  ]
}
```

规则优先级：按数组顺序匹配，命中第一个即停止。


**初始化流程伪代码**：
```javascript
function init(callback) {
  loadConfig().then(function() {
    // 1. 检测登录通道
    if (isInWechat()) {
      initWechatAuth(callback);
    } else {
      initAnonymousAuth(callback);
    }
  });
}

function initWechatAuth(callback) {
  // 从URL取token（微信回调后会在URL里带token）
  var urlParams = new URLSearchParams(location.search);
  var tokenFromUrl = urlParams.get('token');

  if (tokenFromUrl) {
    // 回调成功，保存token
    localStorage.setItem('token', tokenFromUrl);
    // 清理URL
    history.replaceState({}, '', location.pathname);
    // 获取用户信息
    getUserInfo().then(callback);
  } else {
    // 无token，触发静默授权
    var storedToken = localStorage.getItem('token');
    if (storedToken) {
      getUserInfo().then(callback); // 有本地token，验证
    } else {
      redirectToWxOAuth(); // 重定向到微信授权
    }
  }
}
```

### 6.1 新微信用户首次访问

```

  │

  │    │        └→ 失效(401) → 清除token，继续往下
  │    └→ 无
  │
  ▼

  │
```

## 7. 错误处理与降级

### 7.1 降级策略

| 场景 | 行为 |
|------|------|
| 服务端完全不可达 | `serverAvailable = false`，游戏流程继续（localStorage兜底），排行榜显示"暂不可用" |
| 微信OAuth失败 | 降级为匿名登录，用户无感知 |
| 进度同步失败 | 降级为本地存储，后续有网络时重试 |
| token 验证失败(401) | 清除本地token，重新走登录流程 |
| 证书申请失败 | 降级为本地时间戳编号（BM2025+7位） |
| 排行榜加载失败 | 显示"排行榜暂不可用" |
| 成绩提交失败 | 静默失败，不阻塞游戏流程 |

### 7.2 网络状态检测

```javascript
// app.js
var serverAvailable = true;

function checkServer() {
  return fetch('/api/cert/stats', { cache: 'no-store' })
    .then(function(r) { return r.ok; })
    .catch(function() {
      serverAvailable = false;
      return false;
    });
}
```

### 7.3 进度冲突处理

以服务端时间戳为准：
- 用户A在设备1离线游戏了1小时，设备2在线
- 用户A在设备2查看排名，设备1重新联网
- 服务端记录设备2的时间戳更新晚于设备1
- 设备1联网后，服务端数据（设备2的进度）不会被设备1覆盖
- **写入前比较 `last_active_at`**，以最新的为准

```nginx
server {

    server_name museum.example.com;

server {
    listen 443 ssl;
```

## 11. 安全考虑

| 方面 | 措施 |
|------|------|
| 编号伪造 | 证书编号仅服务端生成，客户端无法伪造 |
| 身份冒用 | token 为 32 位随机 hex，暴力破解不可行 |
| OpenID 泄露 | OpenID 是用户在特定公众号下的标识，本身非敏感信息，但仍不推荐在前端 URL 中明文传递长期有效凭证 |
| AppSecret 泄露 | **绝对不能**出现在前端代码、GitHub、日志中，只能在服务端环境变量中 |
| SQL 注入 | `better-sqlite3` 参数化查询，天然防注入 |
| 并发编号重复 | SQLite 事务保证原子递增 |
| 进度篡改 | 服务端校验 unlockedLevels 逻辑合法性（如不能跳关） |
| 接口限流 | 可选：Nginx `limit_req` 模块限制 API 频率 |
| HTTPS | 微信 OAuth 强制要求 HTTPS |
