# 证书与首页布局优化方案

## 1. 概述

在现有"文物拼图大挑战"H5游戏基础上，对证书系统进行升级，新增"首次通关"纪念证书，并优化首页布局。

---

## 2. 证书体系

### 2.1 两张证书定义

| 证书 | Tab标签 | 耗时来源 | 昵称来源 | 日期来源 | 副标题 | 更新规则 |
|------|--------|---------|---------|---------|--------|---------|
| 最速记录 | 🏆 最速记录 | `getTotalTime()` 各关最优之和，实时累加 | `getNickname()` 实时 | 查看当天的日期 | 电子荣誉证书 | 随时变化 |
| 首次通关 | 🥇 首次通关 | `firstCompletionTime` 锁定快照 | `firstCompletionNickname` 锁定快照 | 首次通关那天的日期 | 电子荣誉证书 · 首次通关纪念 | 写入后永久锁定 |

### 2.2 证书编号

两张证书共享同一个 `medalNumber`（格式：`BM2026XXXXXXX`），首次通关时生成，永不改变。编号代表"这个人"而非"这次成绩"。

---

## 3. 首次通关数据模型

### 3.1 快照时机

用户**第一次**完成第5关拼图时，拍下快照并永久锁定：

```javascript
// 此时刻的数据被冻结
firstCompletionTime     = getTotalTime()    // 当前各关最优之和
firstCompletionDate     = "2026年5月8日"     // 当天的日期字符串
firstCompletionNickname = getNickname()      // 当前昵称
```

### 3.2 localStorage 存储

| Key | 数据结构 | 写入时机 | 覆盖规则 |
|-----|---------|---------|---------|
| `firstCompletion` | `{ time: 秒, date: "2026年X月X日", nickname: "玩家昵称" }` | 第一次完成第5关 | 永不覆盖 |
| `levelTimes`（已有） | `{ level1: 秒, level2: 秒, ... }` | 每关完成，更优时写入 | 更优覆盖 |
| `medalNumber`（已有） | `"BM2026837291"` | 第一次完成第5关 | 永不覆盖 |
| `nickname`（已有） | `"玩家昵称"` | 用户在设置页手动修改 | 用户控制 |

### 3.3 app.js 新增方法

| 方法 | 说明 |
|------|------|
| `setFirstCompletion(time, nickname)` | 写入首次通关数据，同时生成 medalNumber |
| `getFirstCompletion()` | 返回 `{ time, date, nickname }` 或 `null` |
| `hasFirstCompletion()` | 返回布尔值，判断是否已有首次通关记录 |
| `resetProgress()` 增强 | 重置时同步清除 `firstCompletion` |

## 4. 第5关完成逻辑

### 4.1 流程图

```
用户完成第5关拼图
  │
  ├─ hasFirstCompletion() === false ?
  │   │
  │   ├─ 是 → 第一次通关
  │   │       ├─ snapshot = getTotalTime()
  │   │       ├─ setFirstCompletion(snapshot, getNickname())
  │   │       │   （内部同时调用 generateMedalNumber()）
  │   │       ├─ 弹出证书弹窗 🎉 恭喜首次通关！
  │   │       │   内容：昵称、总耗时(snapshot)、编号、日期
  │   │       │   按钮：[🏆 查看证书] → 跳转 certificate 页，高亮"首次通关"Tab
  │   │       │         [📥 保存证书] → 保存当前快照的证书图片
  │   │       └─ 主页出现「🏆 证书」按钮
  │   │
  │   └─ 否 → 不是第一次
  │           ├─ 更新 levelTimes（比之前更优则覆盖）
  │           ├─ 完成关卡记录（已存在不重复记录）
  │           └─ 弹出普通文物卡片弹窗（和第1~4关一致）
  │               底部额外多一个 [🏆 查看证书] 按钮
```

### 4.2 第5关普通完成弹窗（非首次）

和第1~4关完成弹窗完全一致（文物图片、名称、年代、描述等），仅底部按钮区差异：

| 按钮 | 第1~4关 | 第5关（非首次） |
|------|--------|---------------|
| 继续挑战 | ✅ | ❌（已是最后一关） |
| 返回首页 | ✅ | ✅ |
| 🏆 查看证书 | ❌ | ✅ 新增 |

### 6.2 Tab 切换数据映射

| 元素 | 「最速记录」Tab | 「首次通关」Tab |
|------|---------------|---------------|
| 副标题 | `电子荣誉证书` | `电子荣誉证书 · 首次通关纪念` |
| 昵称 | `App.getNickname()` | `firstCompletion.nickname` |
| 总耗时 | `App.getTotalTime()` → `App.formatTime()` | `firstCompletion.time` → `App.formatTime()` |

| 日期 | 当天 `new Date()` 格式化 | `firstCompletion.date` |

### 6.3 保存证书

点击「📥 保存证书」→ 直接复用 `GamePage.saveCertificateAsImage(nickname, timeStr, certNum, dateStr, subtitle)`：

- 最速记录 Tab：`subtitle = '电子荣誉证书'`
- 首次通关 Tab：`subtitle = '电子荣誉证书 · 首次通关纪念'`

复用逻辑包括：Canvas 绘制 → PNG 导出 → 覆盖层弹出 → "长按图片保存到相册"提示 → 关闭按钮。

### 6.4 技术要点

- 证书页面的证书预览卡片使用 **纯 CSS 渲染**（DOM），样式与 Canvas 绘制效果保持一致
- 保存图片时才调用 Canvas API 生成高清 PNG
- 不额外编写图片生成代码，完全复用 `GamePage.saveCertificateAsImage()`

## 7. 代码改动清单

### 7.1 `app.js`（约 +30 行）

```javascript
// 新增：首次通关数据存取
var firstCompletion = null;  // { time, date, nickname }

function loadFirstCompletion() {
    try {
        var data = localStorage.getItem('firstCompletion');
        if (data) firstCompletion = JSON.parse(data);
    } catch (e) { firstCompletion = null; }
}

function setFirstCompletion(time, nickname) {
    var now = new Date();
    var dateStr = now.getFullYear() + '年' + (now.getMonth() + 1) + '月' + now.getDate() + '日';
    firstCompletion = { time: time, date: dateStr, nickname: nickname };
    try {
        localStorage.setItem('firstCompletion', JSON.stringify(firstCompletion));
    } catch (e) {}
    generateMedalNumber();  // 证书编号此时生成
}

function getFirstCompletion() { return firstCompletion; }
function hasFirstCompletion() { return firstCompletion !== null && firstCompletion.time > 0; }

// resetProgress() 增加清除 firstCompletion
// init() 增加 loadFirstCompletion() 调用
```

## 8. 场景验证

### 场景1：新用户首次通关

```
主页 → 开始游戏 → 关卡1 → 关卡2 → 关卡3 → 关卡4 → 关卡5
                                                      → 🎉 弹证书弹窗
  setFirstCompletion(520, "玩家小明")
  generateMedalNumber() → "BM2026837291"
  → 最速记录 = 8分40秒   首次通关 = 8分40秒（相同）
  → 主页出现「🏆 证书」按钮
```

### 场景2：用户回刷第2关（变快了）

```
主页 → 选择关卡2 → 完成（1分30秒，比之前快）
  → levelTimes.level2 = 90
  → 最速记录 = 7分45秒（自动变短）
  → 首次通关 = 8分40秒（不变）
```

### 场景3：用户再次打穿第5关

```
主页 → 开始游戏 → ... → 关卡5完成
  → hasFirstCompletion() === true
  → 弹出文物卡片弹窗（镂雕满金漆花鸟纹拔步床详情）
  → 底部 [🏆 查看证书] 按钮
```

### 场景4：用户查看证书

```
主页 → 点击「🏆 证书」
  → 进入证书页，默认显示"最速记录"Tab
  → 最速记录：7分45秒，昵称"玩家小明"，当天日期
  → 点击"首次通关"Tab
  → 首次通关：8分40秒，昵称"玩家小明"，首次通关日期
  → 点击"保存证书" → Canvas绘制 → 长按保存
```

### 场景5：用户修改昵称后查看

```
设置页 → 昵称改为"小张"
  → 最速记录Tab：显示"小张"（实时读取）
  → 首次通关Tab：显示"玩家小明"（锁定快照，不变）
```

### 场景6：重置进度

```
设置页 → 重新开始 → 确认
  → 清除 levelTimes、completedLevels、firstCompletion、medalNumber
  → 主页「🏆 证书」按钮消失
  → 需要重新完成第5关才会再次触发首次通关
```

## 9. 与需求文档的一致性

本方案在原有需求文档基础上做如下调整：

| 需求文档项 | 原方案 | 本方案调整 |
|-----------|--------|-----------|
| 奖牌编号 | BM + 年份4位 + 时间戳后7位 | ✅ 不变 |
| 用户昵称 | 手动输入 > "神秘玩家" | ✅ 不变 |
| 关卡总耗时 | 各关最优之和 | ✅ 不变 |
| 证书保存 | Canvas API 导出 PNG | ✅ 不变，复用原逻辑加 subtitle 参数 |
| 排行榜 | localStorage 排行 | ⏳ 不在本次范围 |

## 10. 边界情况处理

| 场景 | 处理方式 |
|------|---------|
| 首次通关后清除缓存/losslocalStorage | `firstCompletion` 丢失，下次完成第5关重新触发首次通关 |
| 只打到第4关 | 证书入口不出现，`hasFirstCompletion() === false` |
| 首次通关后昵称被修改 | 首次通关证书显示锁定时昵称，最速记录显示当前昵称 |
| localStorage 写入失败 | try-catch 包裹，失败时 Toast 提示 |
| 证书页面未首次通关就访问（URL直入） | 显示"尚未通关"占位提示 |
