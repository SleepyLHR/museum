# 后端功能需求文档（混合登录方案）

> 项目：文物拼多多 · 博物馆拼图游戏
> 版本：v2.0（引入 Node.js 后端，微信静默授权 + 匿名降级）
> 部署环境：Linux 云服务器 + Nginx(HTTPS) + Node.js
> 前置条件：已认证微信服务号

---

## 1. 项目背景

当前为纯前端 H5 应用，所有数据存储在浏览器 localStorage 中，存在以下局限：

| 问题 | 影响 |
|------|------|
| localStorage 隔离 | 换设备/清缓存后数据全部丢失 |
| 证书编号基于时间戳 | `BM2025+7位数字`，无法实现递增编号 |
| 无服务端 | 无法做排行榜、用户统计 |
| 编号不可验证 | 无法判断证书真伪、无法防伪造 |
| 无用户身份 | 每个浏览器是一张白纸，无法跨设备识别 |

引入 Node.js 后端后，核心收益：
- **微信无感登录** 微信内打开 → 静默识别身份 → 换设备数据自动恢复
- **递增证书编号** 000001→999999，逢特殊数字自动识别奖品
- **服务端进度存储** 关卡进度、用时全部上云，localStorage降级为缓存
- **排行榜** 日榜 + 总榜

## 2. 登录方案总览：混合模式

### 2.1 核心策略

```
用户打开页面
  │
  ├─ localStorage 有有效 token？
  │   └─ 有 → 直接使用（最快路径，无需任何网络请求验证）
  │
  └─ 无 token → 检测运行环境
       │
       ├─ 在微信客户端内（User-Agent 含 MicroMessenger）
       │   │
       │   │  301 重定向到微信 OAuth (snsapi_base，静默)
       │   │  微信自动返回 code
       │   │  服务端用 code 换 OpenID
       │   │  按 OpenID 查数据库
       │   │
       │   ├─ 找到老用户 → 返回用户数据 + 新 token
       │   │               → 关卡进度、证书、成绩自动恢复
       │   │
       │   └─ 新用户 → 创建用户 → 返回 token
       │               → 空白新账号开始游戏
       │
       └─ 不在微信（Safari/Chrome/其他App内置浏览器）
           │
           POST /api/user/session (anonymous)
           服务端生成：userId + token
           全新匿名用户，后续可通过证书编号找回
```

### 2.2 各场景用户体验

| 场景 | 用户看到什么 | 数据状态 |
|------|-------------|----------|
| 微信首次打开 | 约1秒白屏 → 直接进首页 | 新账号，第一关未解锁 |
| 微信二次打开 | 瞬间进首页（token命中） | 进度全在 |
| 微信中清缓存 | 约1秒白屏 → 自动恢复 | 同一OpenID，进度全回来 |
| 微信中换手机 | 约1秒白屏 → 自动恢复 | 同一微信号，进度全在 |
| Safari首次打开 | 瞬间进首页 | 匿名新账号 |
| Safari清缓存 | 瞬间进首页但数据丢失 | 匿名新账号（需证书找回） |
| 任何时候网络断开 | 正常游戏（localStorage兜底） | 下次联网时自动同步 |

### 2.3 为什么不用 snsapi_userinfo

- `snsapi_userinfo` 需要用户点击"确认授权"，有流失率
- 本项目不需要微信头像和微信昵称（用户自行设置昵称）
- `snsapi_base` 静默获取 OpenID 足以完成身份识别

## 3. 架构设计

```
┌─────────────────────────────────────────────────────┐
│                  Nginx (:443 HTTPS)                  │
│                                                     │
│  /api/*       ──→ proxy_pass http://127.0.0.1:3001  │
│  /.well-known/*                                     │
│  /*           ──→ 静态文件 (HTML/CSS/JS/images)      │
│                                                     │
│  SSL 证书: Let's Encrypt (免费)                      │
│  微信 OAuth 强制要求 HTTPS                            │
└──────────────┬─────────────────────┬─────────────────┘
               │                     │
    ┌──────────▼──────────┐  ┌──────▼──────────────┐
    │  Node.js (:3001)    │  │  静态文件目录         │
    │  museum-server.js   │  │  index.html          │
    │  data.db (SQLite)   │  │  config.json         │
    │                     │  │  js/ css/ images/    │
    └─────────────────────┘  └──────────────────────┘
```

**技术选型：**

| 组件 | 选择 | 理由 |
|------|------|------|
| 运行时 | Node.js 18+ | 与前端语言统一 |
| HTTP框架 | 原生 `http` 模块 | 功能简单，无需 Express |
| 数据库 | SQLite (better-sqlite3) | 单文件零配置，适合中小规模 |
| HTTPS | Let's Encrypt + Nginx | 免费，微信OAuth强制要求 |
| 进程管理 | pm2 | 自动重启、日志管理 |
| 端口 | 3001（内网，仅 Nginx 可达） | 不对外开放 |

**依赖包：** `better-sqlite3`

## 4. 数据库设计 (SQLite)

### 4.1 users — 用户表（核心）

```sql
CREATE TABLE users (
  id              TEXT PRIMARY KEY,      -- "U" + base36时间戳, 例: U1a2b3c4
  login_type      TEXT NOT NULL,         -- "wechat" | "anonymous"
  openid          TEXT UNIQUE,           -- 微信OpenID (login_type=wechat时有值)
  token           TEXT NOT NULL UNIQUE,  -- 32位hex, API认证凭证
  nickname        TEXT DEFAULT '神秘玩家',
  created_at      TEXT NOT NULL,         -- ISO 8601
  last_active_at  TEXT NOT NULL
);
CREATE UNIQUE INDEX idx_users_openid ON users(openid) WHERE openid IS NOT NULL;
CREATE UNIQUE INDEX idx_users_token ON users(token);
```

**设计要点：**
- `openid` 允许 NULL（匿名用户无此值），但非NULL时唯一约束
- `login_type` 区分用户来源：`wechat` / `anonymous`
- `token` 是前端持有的唯一凭证；更换 token 即令旧 token 失效
- `id` 仅用于对外展示，所有服务端关联用 `id`

### 4.2 user_progress — 游戏进度表

```sql
CREATE TABLE user_progress (
  user_id         TEXT PRIMARY KEY,
  completed_levels TEXT NOT NULL DEFAULT '[]',   -- JSON数组 ["level1","level2"]
  unlocked_levels TEXT NOT NULL DEFAULT '["level1"]', -- JSON数组
  level_times     TEXT NOT NULL DEFAULT '{}',    -- JSON对象 {"level1":120,"level2":90,...}
  total_time      INTEGER NOT NULL DEFAULT 0,    -- 总用时（秒），冗余便于查询
  has_completed   INTEGER NOT NULL DEFAULT 0,    -- 0=未通关 1=已通关
  first_completed_at TEXT,                        -- 首次通关时间 ISO 8601
  updated_at      TEXT NOT NULL,
  FOREIGN KEY (user_id) REFERENCES users(id)
);
```

**设计要点：**
- 与 `users` 表一对一，分离关注点（身份 vs 游戏数据）
- 进度字段用 JSON 存储，灵活性好，SQLite 直接读写字符串
- `has_completed` 布尔标记，方便快速筛选（排行榜只统计已通关用户）
- `total_time` 冗余字段，避免每次查询都要解析 JSON 计算

### 4.3 certificates — 证书表

```sql
CREATE TABLE certificates (
  cert_number  TEXT PRIMARY KEY,    -- "000001" ~ "999999"
  user_id      TEXT NOT NULL,
  nickname     TEXT NOT NULL,       -- 锁定快照（通关瞬间的昵称）
  total_time   INTEGER NOT NULL,    -- 锁定快照（通关瞬间的总用时）
  is_special   INTEGER DEFAULT 0,   -- 0=普通 1=特殊号码
  prize        TEXT,                -- 奖品名称
  created_at   TEXT NOT NULL,
  FOREIGN KEY (user_id) REFERENCES users(id)
);
CREATE INDEX idx_certs_user ON certificates(user_id);
```

**设计要点：**
- 每个用户只有一条证书记录（通关时写入，后续同一用户不重复生成）
- `nickname` 和 `total_time` 锁定快照，不随后续修改变化
- `is_special` 和 `prize` 服务端自动判定

### 4.4 cert_counter — 编号计数器

```sql
CREATE TABLE cert_counter (
  id            INTEGER PRIMARY KEY DEFAULT 1,
  current_value INTEGER NOT NULL DEFAULT 0
);
-- 初始: INSERT INTO cert_counter (current_value) VALUES (0);
```

原子递增逻辑：事务内 `UPDATE + SELECT`，保证并发安全。

### 4.5 scores — 总榜成绩表

```sql
CREATE TABLE scores (
  user_id    TEXT PRIMARY KEY,
  nickname   TEXT NOT NULL,
  total_time INTEGER NOT NULL,     -- 当前最佳总用时（秒）
  updated_at TEXT NOT NULL,
  FOREIGN KEY (user_id) REFERENCES users(id)
);
CREATE INDEX idx_scores_time ON scores(total_time);
```

**设计要点：**
- 每个用户一条记录，通关时更新（仅当新成绩更优时更新）
- 排行榜查询：`SELECT * FROM scores ORDER BY total_time ASC LIMIT ? OFFSET ?`

### 4.6 daily_scores — 日榜成绩表

```sql
CREATE TABLE daily_scores (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id    TEXT NOT NULL,
  nickname   TEXT NOT NULL,
  total_time INTEGER NOT NULL,
  score_date TEXT NOT NULL,        -- "2026-05-09"
  created_at TEXT NOT NULL,
  FOREIGN KEY (user_id) REFERENCES users(id)
);
CREATE INDEX idx_daily_date_time ON daily_scores(score_date, total_time);
```

**设计要点：**
- 每天可能多条记录（用户多次刷新成绩），日榜取当天 `MIN(total_time) GROUP BY user_id`
- 按北京时间 00:00 切换日期

### 4.7 cert_recovery_log — 证书恢复日志

```sql
CREATE TABLE cert_recovery_log (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  cert_number TEXT NOT NULL,
  new_token   TEXT NOT NULL,
  recovered_at TEXT NOT NULL
);
CREATE INDEX idx_recovery_cert ON cert_recovery_log(cert_number);
```

用于限制同一证书恢复次数（建议最多 3 次）。

## 5. API 设计

全部接口前缀：`/api`

### 5.1 会话类（用户登录）

#### POST /api/user/session

> 统一的用户登录入口（合并微信回话和匿名注册）

**匿名注册请求：**
```json
{
  "loginType": "anonymous"
}
```

**匿名注册响应：**
```json
{
  "userId": "U1a2b3c4",
  "token": "a1b2c3d4e5f67890...32位hex",
  "nickname": "神秘玩家",
  "loginType": "anonymous",
  "isNew": true,
  "progress": {
    "completedLevels": [],
    "unlockedLevels": ["level1"],
    "levelTimes": {},
    "totalTime": 0,
    "hasCompleted": false
  }
}
```

**微信 OAuth 回调请求：**
前端不直接调用此接口。微信回调 `/api/wx/cb` 后，服务端内部调用此逻辑。

**响应字段说明：**

| 字段 | 说明 |
|------|------|
| `isNew` | 是否新用户，前端据此决定是否显示新手引导 |
| `progress` | 游戏进度对象，老用户恢复时包含之前的所有进度 |

**服务端匿名注册逻辑：**
1. 生成 32 位随机 hex token
2. 生成 userId = `U` + base36(timestamp + random)
3. INSERT users、INSERT user_progress
4. 返回

**服务端微信登录逻辑：**
1. 用 code 调用微信接口获取 OpenID
2. `SELECT * FROM users WHERE openid = ?`
3. 找到了 → 生成新 token，更新 last_active_at，读取 user_progress，返回
4. 未找到 → 同匿名注册流程，额外写入 openid 和 login_type='wechat'

---

### 5.2 微信 OAuth 回调（特殊路由）

#### GET /api/wx/cb

> 微信 OAuth 回调地址，由微信服务器302跳转到此

```
GET /api/wx/cb?code=021aBcDeFgHiJk...&state=abc123
```

**服务端处理流程：**
```
1. 接收 code 参数
2. POST https://api.weixin.qq.com/sns/oauth2/access_token
   ?appid={APPID}&secret={APPSECRET}&code={code}&grant_type=authorization_code
3. 从微信响应中提取 openid
4. 执行微信登录逻辑（查数据库 / 创建用户）
5. 生成新 token
6. 302 重定向到前端首页：
   /#/home?token={新token}&isNew={true|false}
```

**错误处理：**
- code 无效 → 302 回首页，不带 token，前端走匿名注册
- 微信接口超时 → 同上

**前端接收：**
```
URL hash 中检测到 token 参数
→ localStorage.setItem('token', token)
→ 按正常流程初始化
→ remove token from URL（清理地址栏）
```

### 5.3 用户类

#### GET /api/user/info

> 获取当前用户完整信息（含游戏进度）

请求头：
```
Authorization: Bearer <token>
```

响应：
```json
{
  "userId": "U1a2b3c4",
  "nickname": "张三",
  "loginType": "wechat",
  "createdAt": "2026-05-09T10:30:00.000Z",
  "progress": {
    "completedLevels": ["level1", "level2"],
    "unlockedLevels": ["level1", "level2", "level3"],
    "levelTimes": { "level1": 120, "level2": 90 },
    "totalTime": 210,
    "hasCompleted": false
  }
}
```

认证失败 → 401

#### PUT /api/user/nickname

> 修改昵称

请求头：
```
Authorization: Bearer <token>
```

请求体：
```json
{ "nickname": "张三" }
```

响应：
```json
{ "success": true, "nickname": "张三" }
```

**注意：** 昵称修改后，排行榜上的昵称是否随之更新由产品决定。建议**排行榜实时反映最新昵称**，证书保持通关瞬间的快照。

#### POST /api/user/progress/sync

> 同步游戏进度到服务端（通关每关后、游戏过程中的关键节点调用）

请求头：
```
Authorization: Bearer <token>
```

请求体：
```json
{
  "completedLevels": ["level1", "level2"],
  "unlockedLevels": ["level1", "level2", "level3"],
  "levelTimes": { "level1": 120, "level2": 90 },
  "levelTime": 90,
  "levelId": "level2"
}
```

响应：
```json
{ "success": true, "syncedAt": "2026-05-09T11:00:00.000Z" }
```

**设计要点：**
- 每次完成一关后调用，同时传递增量 `levelTime` + `levelId` 和全量 `completedLevels`/`unlockedLevels`
- 服务端合并逻辑：取 max(completedLevels)、max(unlockedLevels)、每个关卡的 min(time)
- 这个接口也用于后台静默同步（定时器或页面隐藏时触发）

#### POST /api/user/recover

> 匿名用户更换设备/清缓存后，通过证书编号 + 昵称找回身份

请求体：
```json
{
  "certNumber": "000123",
  "nickname": "张三"
}
```

响应（成功）：
```json
{
  "success": true,
  "userId": "U1a2b3c4",
  "token": "新的32位hex",
  "certNumber": "000123",
  "totalTime": 360,
  "progress": {
    "completedLevels": ["level1","level2","level3","level4","level5"],
    "unlockedLevels": ["level1","level2","level3","level4","level5"],
    "levelTimes": { ... },
    "totalTime": 360,
    "hasCompleted": true
  }
}
```

失败：
```json
{ "success": false, "message": "证书编号与昵称不匹配" }
```

或：
```json
{ "success": false, "message": "该证书恢复次数已达上限" }
```

**安全设计：**
- 双重匹配 `certNumber` + `nickname`
- 同一证书最多被恢复 3 次（查 `cert_recovery_log`）
- 恢复成功后生成新 token，旧 token 失效
- 恢复后不改变用户的 `login_type`（仍是 anonymous）

**注意：** 微信用户（login_type=wechat）不需要走此流程，换设备后静默OAuth自动识别。

### 5.4 证书类

#### POST /api/cert/apply

> 首次通关时申请证书编号（幂等）

请求头：
```
Authorization: Bearer <token>
```

请求体：
```json
{
  "totalTime": 360,
  "nickname": "张三"
}
```

响应：
```json
{
  "certNumber": "000888",
  "isSpecial": true,
  "prize": "三等奖 - 精美文创礼品",
  "totalCerts": 888
}
```

**服务端逻辑：**
1. 验证 token → 获取 userId
2. 检查 `certificates` 表，该用户是否已有证书
   - 已有 → 直接返回已有编号（幂等，不会重新生成）
3. 原子递增计数器 → 生成 6 位编号
4. 检测特殊号码规则 → 匹配则标记
5. 写入 certificates 表
6. 更新 user_progress 的 `has_completed` 和 `first_completed_at`
7. 返回结果

## 6. 前端改造

### 6.1 app.js — 核心改造（幅度最大）

| 改动 | 说明 |

**`resolveSession()` 核心流程：**

```
function resolveSession() {
  // 1. 检查 URL hash 中是否有微信回调的 token
  var hashParams = parseHashParams();
  if (hashParams.token) {
    localStorage.setItem('token', hashParams.token);
    // 清理 URL 中的 token
  }

  // 2. 读取 localStorage token
  var token = localStorage.getItem('token');

  // 3. 有 token → 用 /api/user/info 验证并恢复进度
  if (token) {
    return callApi('GET', '/user/info').then(function(user) {
      restoreProgress(user.progress);
      return user;
    }).catch(function() {
      // token 失效 → 清除 → 走无 token 流程
      localStorage.removeItem('token');
      return resolveSession();
    });
  }

  // 4. 无 token → 检测微信环境
  if (isWechat()) {
    // 重定向到微信 OAuth
    redirectToWechatOAuth();
    return Promise.reject('OAUTH_REDIRECT');
  }

  // 5. 非微信 → 匿名注册
  return callApi('POST', '/user/session', {
    loginType: 'anonymous'
  }).then(function(user) {
    localStorage.setItem('token', user.token);
    restoreProgress(user.progress);
    return user;
  }).catch(function() {
    // 网络不可用 → 纯 localStorage 模式
    serverAvailable = false;
    return null;
  });
}
```

**`restoreProgress()` 逻辑：**
```
服务端进度 vs localStorage进度 → 取最优（合并）
- completedLevels: 取并集
- unlockedLevels: 取并集（最大范围）
- levelTimes: 每关取最小值
```

### 6.2 进度同步机制

```
每完成一关:
  app.completeLevel(levelId)
  → 更新 state + localStorage
  → 异步调用 POST /api/user/progress/sync (fire-and-forget，不阻塞)

页面隐藏/关闭时:
  → 静默调用 syncProgress（sendBeacon或fetch keepalive）

服务端不可达:
  → syncProgress 静默失败
  → 下次成功连接时，app.init 中的 restoreProgress 自动合并
```

**核心原则：localStorage 是缓存，服务端是主数据源。网络正常时以服务端为准，网络断开时游戏照常运行。**

## 7. 完整业务流程

### 7.1 微信用户首次访问

```
用户在微信中点击链接
  │
  ▼
H5 页面加载 → app.js init()
  │
  ▼
localStorage 无 token
  │
  ▼
检测到微信环境（UA 含 MicroMessenger）
  │
  ▼
301 跳转到微信 OAuth 授权页
  https://open.weixin.qq.com/connect/oauth2/authorize
    ?appid={APPID}
    &redirect_uri=https://museum.example.com/api/wx/cb
    &response_type=code
    &scope=snsapi_base
    &state=random
    #wechat_redirect
  │ (用户屏幕短暂白屏 1-2秒，无任何弹窗)
  ▼
微信服务器处理 → 302 回调到 /api/wx/cb?code=xxx&state=xxx
  │
  ▼
服务端 /api/wx/cb 处理：
  1. 用 code 调微信 API 换 OpenID
  2. 查 users 表 → 无记录（新用户）
  3. INSERT users（login_type=wechat, openid=xxx）
  4. INSERT user_progress（初始空进度）
  5. 生成 token
  6. 302 → /#/home?token={token}&isNew=true
  │
  ▼
前端接收：
  1. 从 URL 取 token → localStorage.setItem('token', ...)
  2. 新用户 → 展示首页，第一关可玩
  3. 清理 URL 中的 token 参数
```

## 8. 错误处理与降级

### 8.1 降级策略

| 场景 | 行为 |
|------|------|
| 服务端完全不可达 | `serverAvailable = false`，全部功能降级 localStorage |
| 微信 OAuth 超时/失败 | 302 回首页不带 token → 前端走匿名注册 |
| 创建会话失败 | 使用本地 userId（当前代码的 `settings.getUserId()` 逻辑） |
| 证书申请失败 | 回退原有时间戳编号 `BM2025+7位数字` |
| 进度同步失败 | 静默失败，下次联网自动合并 |
| 排行榜加载失败 | 显示"排行榜暂不可用" |
| 成绩提交失败 | 本地记录，下次联网补提交 |

### 8.2 数据一致性保障

```
数据优先级：服务端 > localStorage

冲突解决（restoreProgress）：
- completedLevels: 取并集 (服务端 ∪ 本地)
- unlockedLevels: 取并集 (服务端 ∪ 本地)
- levelTimes: 每关取 min(服务端, 本地)

这个策略确保：
- 服务端有的进度不会丢失
- 本地离线打的进度不会丢失
- 两边都有时取最优成绩
```

## 9. 安全考虑

| 方面 | 措施 |
|------|------|
| 编号伪造 | 证书编号仅服务端生成，客户端不可伪造 |
| 身份冒用 | token 为 32 位随机 hex，不可暴力破解 |
| Token 泄露 | 服务端可随时更换 token 使旧 token 失效 |
| 恢复滥用 | 同一证书恢复次数限制（3次） |
| AppSecret 泄露 | 仅存于服务端环境变量，前端不可见 |
| SQL 注入 | better-sqlite3 参数化查询 |
| 并发编号 | SQLite 事务保证原子递增 |
| OpenID 隐私 | 仅存于服务端数据库，不暴露给前端 |
| 接口限流 | Nginx `limit_req`（可选） |
