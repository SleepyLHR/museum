# 后端功能需求文档 v3.0

> 项目：文物拼多多 · 博物馆拼图游戏
> 版本：v3.0（用户身份系统 + 游戏进度同步）
> 部署环境：Linux 云服务器 + Nginx + Node.js
> 说明：本文档聚焦用户身份与进度同步，证书编号与排行榜见独立文档

---

## 1. 项目背景与目标

### 现状

当前为纯前端 H5 应用，所有数据存储在浏览器 localStorage 中：

| 问题 | 影响 |
|------|------|
| localStorage 隔离 | 换设备/清缓存后数据全部丢失 |
| 无用户身份 | 无法识别用户、无法关联用户数据 |
| 无进度持久化 | 进度随浏览器数据清除而消失 |

### 目标

- **用户身份识别**：微信环境静默授权，非微信环境匿名注册，零操作完成
- **进度服务端持久化**：游戏进度（关卡解锁、完成、用时）实时同步到服务端
- **换设备恢复**：微信用户换设备后自动识别，历史进度完整保留
- **配置化设计**：微信授权通过开关控制，灵活切换是否启用微信认证

### 2.2 登录通道与开关

`wxAuthEnabled` 是全局开关，定义在服务端配置文件 `server/config.js` 中：

| wxAuthEnabled | 微信环境 | 非微信环境 | 说明 |
|---|---|---|---|
| `true` | 静默OAuth授权（snsapi_base） | 匿名注册 | 正式运营模式 |
| `false` | 匿名注册 | 匿名注册 | 开发调试模式 |

开关切换不需要改代码，只需要在服务端配置文件修改值，重启服务即可生效。

### 2.3 技术选型

| 组件 | 选择 | 说明 |
|------|------|------|
| 运行时 | Node.js 18+ | 与前端语言统一 |
| 框架 | 原生 `http` 模块 | 功能简单，无需 Express |
| 数据库 | SQLite (better-sqlite3) | 单文件零配置 |
| 进程管理 | pm2 | 自动重启、日志管理 |
| 端口 | 3001（内网） | Nginx 反向代理 |
| SSL | Let's Encrypt（免费） | Nginx 配置 |

## 3. 数据库设计 (SQLite)

### 3.1 users — 用户表

```sql
CREATE TABLE users (
  id               TEXT PRIMARY KEY,       -- 服务端生成: "U"+base36时间戳
  openid           TEXT UNIQUE,             -- 微信OpenID，微信用户独有，匿名用户为NULL
  token            TEXT NOT NULL UNIQUE,    -- 32位hex随机字符串，Bearer认证
  nickname         TEXT DEFAULT '神秘玩家',
  -- 游戏进度
  unlocked_levels  TEXT DEFAULT '["level1"]',  -- JSON数组
  completed_levels TEXT DEFAULT '[]',             -- JSON数组
  level_times      TEXT DEFAULT '{}',             -- JSON对象 {levelId: seconds}
  total_time       INTEGER DEFAULT 0,             -- 各关累计总用时（秒）
  -- 元数据
  is_anonymous     INTEGER DEFAULT 1,             -- 1=匿名用户 0=微信用户
  created_at       TEXT NOT NULL,                 -- ISO 8601
  last_active_at   TEXT NOT NULL                  -- ISO 8601
);
```

**设计要点**：
- `openid` 唯一索引：微信用户通过 openid 跨设备识别
- 匿名用户 `openid = NULL`，不具有跨设备能力
- `level_times` / `unlocked_levels` / `completed_levels` 同步到服务端，作为唯一真实数据源

## 4. API 设计

全部接口前缀：`/api`

### 4.1 微信授权类

#### GET /api/wx/callback

> 微信 OAuth 回调接口（仅 wxAuthEnabled=true + 微信环境时使用）
> 接收 code，换 OpenID，识别/创建用户，重定向回前端

请求：
```
GET /api/wx/callback?code=xxxxx&state=yyyy
```

服务端处理流程：
1. 验证 state 防 CSRF
2. 用 code + AppSecret 向微信服务器换 OpenID
3. 用 OpenID 查 users 表
   - **找到** → 老用户 → 更新 `last_active_at`，生成新 token
   - **未找到** → 新用户 → 创建记录，生成 token
4. 302 重定向：`https://<域名>/#/?token=<token>`

返回：302 重定向，无 JSON 响应体

错误重定向：
- code 无效 → `https://<域名>/#/home?error=wx_auth_failed`
- 服务端异常 → `https://<域名>/#/home?error=wx_auth_error`

#### GET /api/wx/jsapi-config

> 获取微信 JS-SDK 签名（预留，后续分享等功能可能用到）

请求参数：
```
?url=https://museum.com/game/level1
```

响应：
```json
{
  "appId": "wx1234567890abcdef",
  "timestamp": 1746938456,
  "nonceStr": "randomstr123",
  "signature": "xxxxxxxxxxxx"
}
```

### 4.2 用户类

#### POST /api/user/session

> 统一会话入口
> - 微信用户：验证/创建会话，返回用户信息 + 进度
> - 匿名用户：创建会话，返回用户信息 + 进度

请求头（有 token 时）：
```
Authorization: Bearer <token>
```
请求体：
```json
{}
```

响应（微信用户 / 匿名用户）：
```json
{
  "userId": "U1a2b3c4",
  "token": "a1b2c3d4e5f6...32位hex",
  "nickname": "神秘玩家",
  "unlockedLevels": ["level1"],
  "completedLevels": [],
  "levelTimes": {},
  "totalTime": 0,
  "isAnonymous": true,
  "isNew": true
}
```

响应（老用户再次访问）：
```json
{
  "userId": "U1a2b3c4",
  "token": "新token",
  "nickname": "张三",
  "unlockedLevels": ["level1", "level2", "level3"],
  "completedLevels": ["level1", "level2"],
  "levelTimes": { "level1": 30, "level2": 45 },
  "totalTime": 75,
  "isAnonymous": false,
  "isNew": false
}
```

**接口逻辑**：

```
前置：wxAuthEnabled 配置决定了是否识别 OpenID

请求中带 token？
  ├→ 有 → 验证 token
  │        ├→ 有效 → 返回用户信息 + 进度
  │        └→ 无效(401) → 清除token，按无token处理
  └→ 无
       ├→ 有 OpenID（wxAuthEnabled=true + 微信环境）
       │    → 用 OpenID 查表
       │    ├→ 找到 → 更新last_active_at + 生成新token → 返回
       │    └→ 未找到 → 创建微信用户 + token → 返回
       └→ 无 OpenID（wxAuthEnabled=false 或 非微信环境）
            → 创建匿名用户 + token → 返回
```

#### GET /api/user/info

> 获取当前用户信息

请求头：
```
Authorization: Bearer <token>
```

响应：
```json
{
  "userId": "U1a2b3c4",
  "nickname": "张三",
  "openid": "oABC123...",    // 仅微信用户有，匿名用户为 null
  "isAnonymous": false,

}
```

认证失败 → 401

#### PUT /api/user/nickname

> 修改昵称

请求头：
```
Authorization: Bearer <token>
```
请求体：
```json
{ "nickname": "张三" }
```

响应：
```json
{ "success": true, "nickname": "张三" }
```

### 4.3 进度同步类

#### GET /api/user/progress

> 拉取游戏进度（换设备后恢复、或主动同步）

请求头：
```
Authorization: Bearer <token>
```

响应：
```json
{
  "unlockedLevels": ["level1", "level2", "level3"],
  "completedLevels": ["level1", "level2"],
  "levelTimes": { "level1": 30, "level2": 45 },
  "totalTime": 75,
  "syncedAt": "2026-05-09T10:30:00.000Z"
}
```

#### POST /api/user/progress

> 上报游戏进度（关卡完成/解锁/用时变化时调用）

请求头：
```
Authorization: Bearer <token>
```
请求体：
```json
{
  "unlockedLevels": ["level1", "level2", "level3"],
  "completedLevels": ["level1", "level2"],
  "levelTimes": { "level1": 30, "level2": 45 },
  "totalTime": 75
}
```

响应：
```json
{ "success": true, "syncedAt": "2026-05-09T10:35:00.000Z" }
```

**同步策略**：
- 每次关卡完成 → 即时上报
- 每次关卡解锁 → 即时上报
- 每次用时刷新 → 即时上报
- 前端本地实时更新，服务端异步持久化

**服务端校验（防跳关）**：
- 允许解锁当前最高关卡的下一关
- 禁止跳过多个关卡同时解锁
- 解锁的关卡必须已完成前置关卡

```javascript
  });

function initSession(callback) {
  var storedToken = localStorage.getItem('token');
  var storedUserId = localStorage.getItem('userId');
  var storedNickname = localStorage.getItem('nickname');

  // 统一走 session 接口
  callApi('POST', '/api/user/session').then(function(data) {
    // 保存 token
    localStorage.setItem('token', data.token);
    localStorage.setItem('userId', data.userId);
    localStorage.setItem('nickname', data.nickname);

    // 如果是换设备（本地进度与服务端不一致），以服务端为准
    if (data.unlockedLevels) {
      // 替换本地进度
      App.state.unlockedLevels = data.unlockedLevels;
      App.state.completedLevels = data.completedLevels;
      saveUserData();
      saveLevelTimes();
    }

    if (callback) callback();
  }).catch(function() {
    // 服务端不可用，降级到纯本地模式
    serverAvailable = false;
    if (callback) callback();
  });
}
```

## 6. 完整业务流程

### 6.1 新用户首次访问（wxAuthEnabled=true）

```
用户点击微信分享卡片
  │
  ▼
微信内置浏览器打开页面
  │
  ▼
app.js init() → initSession()
  │
  ▼
localStorage 无 token
  │
  ▼
POST /api/user/session
  │
  ├→ 前端无 token，服务端检测到微信环境 + wxAuthEnabled=true
  │    → 自动启用微信静默OAuth流程
  │    → 重定向到微信授权页（用户无感知）
  │    → 微信回调 /api/wx/callback → 换取OpenID
  │    → 创建微信用户，生成 token
  │    → 302 回到前端 ?token=xxx
  │
  ├→ 前端从 URL 取 token → 保存到 localStorage
  │    → 清理 URL 参数
  │    → POST /api/user/session（带token）验证
  │    → 获取完整用户信息 + 进度
  │    → 进入首页 ✅
  │
  ▼
正常使用（游戏、图库、设置...）
```

### 6.2 新用户首次访问（wxAuthEnabled=false）

```
用户在微信中打开页面
  │
  ▼
initSession() → POST /api/user/session（无token）
  │
  ├→ 服务端检测到 wxAuthEnabled=false
  │    → 跳过微信OAuth，走匿名注册
  │    → 创建匿名用户，生成 token
  │    → 返回用户信息
  │
  ▼
前端保存 token
  │
  ▼
进入首页 ✅（同非微信环境）
```

### 6.3 老用户再次访问（任意环境）

```
用户再次打开页面
  │
  ▼
initSession() → POST /api/user/session（带本地token）
  │
  ├→ token 有效 → 返回用户信息 + 最新进度
  │    → 前端对比本地与服务端进度
  │    → 以服务端为准同步到本地
  │    → 进入首页 ✅
  │
  └→ token 无效(401) → 清除本地token
       → 重新走新用户流程
```

### 6.4 微信用户换设备

```
同一微信号在新手机打开
  │
  ▼
触发静默OAuth → 换取OpenID
  │
  ▼
服务端：OpenID 查到老用户记录
  → 生成新 token
  → 更新 last_active_at
  → 返回完整用户数据（包括历史进度）
  │
  ▼
前端同步服务端进度到本地
  → 进入首页，所有关卡状态与旧设备一致 ✅
```

### 6.5 普通关卡完成流程

```
用户完成第N关
  │
  ▼
game.js completeLevel()
  │
  ├→ App.completeLevel() 更新本地状态
  │
  ├→ App.setLevelTime() 更新用时
  │
  └→ App.syncProgress() 上报到服务端
       POST /api/user/progress
         { unlockedLevels, completedLevels, levelTimes, totalTime }
```

## 7. 错误处理与降级

### 7.1 降级策略

| 场景 | 行为 |
|------|------|
| 服务端完全不可达 | `serverAvailable = false`，游戏流程继续（localStorage兜底），进度同步静默跳过 |
| token 验证失败(401) | 清除本地token，重新走登录流程 |
| 进度同步失败 | 降级为本地存储，后续重试 |
| 微信OAuth失败 | 降级为匿名登录（wxAuthEnabled=false 模式），用户无感知 |
| 服务端返回 5xx | 降级为本地模式，静默重试 |

### 7.2 服务可用性检测

```javascript
// app.js
var serverAvailable = true;

function checkServer() {
  return fetch('/api/user/info', {
    method: 'GET',
    headers: { 'Authorization': 'Bearer ' + (localStorage.getItem('token') || '') }
  }).then(function(r) {
    serverAvailable = true;
    return true;
  }).catch(function() {
    serverAvailable = false;
    return false;
  });
}
```

服务端所有可配置变量集中在 `server/config.example.js` 中：

```
server/
├── config.example.js   ← 配置模板（复制为 config.js 后填写实际值）
└── config.js          ← 实际使用的配置文件（不提交到仓库）
```

**部署步骤**：

```bash
# 1. 复制配置模板
cp config.example.js config.js

# 2. 编辑 config.js，填入实际值
vim config.js

# 3. 启动服务（会自动读取 config.js）
node museum-server.js
```

### 9.4 Nginx 配置

```nginx
server {
    listen 80;
    server_name museum.example.com;
    return 301 https://$server_name$request_uri;
}

server {
    listen 443 ssl;
    server_name museum.example.com;

    ssl_certificate /etc/letsencrypt/live/museum.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/museum.example.com/privkey.pem;

    root /opt/museum/h5;
    index index.html;

    # API 代理
    location /api/ {
        proxy_pass http://127.0.0.1:3001;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }

    # 微信OAuth回调（仅 wxAuthEnabled=true 时被调用）
    location /wx/ {
        proxy_pass http://127.0.0.1:3001;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }

    location / {
        try_files $uri $uri/ /index.html;
    }
}
```

## 11. 安全考虑

| 方面 | 措施 |
|------|------|
| 身份冒用 | token 为 32 位随机 hex，暴力破解不可行 |
| OpenID 泄露 | OpenID 是用户在特定公众号下的标识，本身非敏感信息 |
| AppSecret 泄露 | **绝对不能**出现在前端代码、GitHub、日志中 |
| SQL 注入 | `better-sqlite3` 参数化查询，天然防注入 |
| 跳关作弊 | 服务端校验 unlockedLevels 逻辑合法性 |
| 进度篡改 | 服务端以时间戳或关卡完成顺序校验 |
| CSRF | 微信 OAuth 的 state 参数防 CSRF |
